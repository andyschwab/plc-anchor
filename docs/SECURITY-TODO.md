# Security review — findings & resolutions

A ledger of the security findings raised against DIDMARC and how each was resolved. Three rounds:
the **June 2026 internal audit** (items 1–6), the **July 2026 design review** (4a–4d), and the
**July 2026 strategy review** (4e). All are resolved; the substance lives in the code and in
[`HISTORY.md`](HISTORY.md) / [`REFERENCE.md`](../REFERENCE.md) — this file is the index the code
comments cite by ID. The outstanding work is the deliberately deferred item (4c) and 4e's
policy residual, tracked in `HISTORY.md` follow-ups.

## July 2026 strategy review (4e)

Raised while re-examining verify-on-read against the spam risk it introduced (the review that
reaffirmed verify-on-read — `HISTORY.md` "Strategy review", 2026-07-08).

| id | sev | finding | resolution |
|---|---|---|---|
| **4e** | MEDIUM | **Anchor-log junk = per-DID witness silencing; anchor read path unbounded.** The anchor's writes are permissionless and its log append-only, and the witness *truncated* chain validation at the first undecodable/invalid op (`deriveAnchorLive`). So one cheap junk `submit_op` to a targeted DID permanently froze the witness's view at the pre-junk head — every real op stored after it invisible: a one-op, few-STRK **silencing of the witness for exactly the DID an attacker cares about** (fail-safe — status decays to stale `tentative-consistent`, never a false `diverged` — but it quietly removes the protection). Independently, the anchor read path had **no ops/bytes bounds** (the directory path has `MAX_AUDIT_ENTRIES`/`MAX_AUDIT_BODY_BYTES`), so a gas-paid bloat of one DID's log could push its `chain()` read past RPC/CPU limits and make its status uncomputable — the **more-exposed surface (permissionless writes) was the less-defended one** (the operator-run directory already had caps). | **Fixed (witness), 2026-07-08.** (1) **Skip, don't truncate:** `deriveAnchorLive` skips undecodable bytes and replays the rest in `deriveLiveChain`'s new `onInvalid: "skip"` mode — a log-*assembly* policy for the permissionless anchor log only (per-op validity + the recovery rule are unchanged, and the directory path keeps stop-mode, faithful to `@did-plc/lib`). Safe because a skipped entry failed the very checks that would have kept it off the live chain — skip-mode over a log ≡ stop-mode over its valid subsequence; junk can hide nothing and confirm nothing. (2) **Bounds mirroring the directory's:** `MAX_ANCHOR_OPS` (10 000) / `MAX_ANCHOR_LOG_BYTES` (8 MiB), checked before any decode/crypto, plus a 32 MiB cap on the `starknet_call` response body; overflow → `check()` returns **`error` (`anchor-log-overflow`)** — unavailable, never a verdict (§0-safe). Pinned in `witness-ts/test/nullified.test.ts` (interleaved-junk silencing regression, stop-vs-skip contrast, overflow → `error`). **Policy residual (tracked, `HISTORY.md` follow-ups):** operator-gate `submit_op` via the console roster (item 6 — the permissionless path is an explicit backstop), and a 7 500-byte per-op structural cap in `anchor.cairo` on the next redeploy. Deliberately **no** in-contract per-DID op-count cap while writes are permissionless — an attacker filling it would lock out the DID's real future ops (spam → lockout). |

## July 2026 design review (4a–4d)

| id | sev | finding | resolution |
|---|---|---|---|
| **4d** | HIGH | **Verify-on-read equivocation suppression.** An interim v2 build validated the anchor chain by *content-addressed cross-reference* against op bodies fetched from the directory under test. An equivocating directory serves a forged log and so never serves the anchored head's op body → the witness couldn't validate the real head and silently lowered its derived confirmed head to a point on the equivocator's own chain → `tentative-consistent`, **suppressing `diverged`** exactly against the primary threat (a hostile directory). A false *negative* (never breaks §0), but it guts the guarantee. | **Fixed before v2 cutover.** The witness now **decodes the anchor's on-chain bytes itself** (new strict `decodeDagCbor`, inverse of the encoder) and derives the confirmed head from bytes only the *anchor* controls — no directory input. A validly-signed op is still required to advance the head (no false positive from a permissionless bogus append; non-canonical bytes are rejected → dropped). Pinned: `witness-ts/test/dagcbor.test.ts` + `nullified.test.ts` (equivocation/garbage). Detail: `HISTORY.md` "Security correction (2026-07-03)"; `docs/ONCHAIN-REARCH-PLAN.md` §1 correction. |
| **4a** | CRITICAL | `import` stamped backfilled ops with the import block time, giving the *entire* history a live 72h recovery window — so for 72h after onboarding a **rotated-out** higher-priority key could fork below the real history and capture the DID (and the anchor would then read `diverged` against an honest directory, the §0-forbidden false alarm). | **Fixed.** Imported ops are marked *settled* (`imported` flag) and a recovery may not nullify one (`recovery-of-imported`); ingest onboards via one settled `import` chain (`onboard_via_import`). *(verify-on-read update, 2026-07-02: the contract still records the `imported` flag; the guard is now **enforced read-side** by the witness — `deriveLiveChain`'s imported branch, mirror of `state::apply_op` — pinned in `witness-ts/test/nullified.test.ts`. The Cairo `state::apply_op` guard remains as the reference.)* Detail: `HISTORY.md` "Security fix 4a" + "Rearchitecture — verify-on-read"; `REFERENCE.md` §5. |
| **4b** | LOW | The read-side recovery re-derivation (`deriveLiveChain`) evaluates the 72h window using the directory-asserted `createdAt`; a hostile mirror could re-time a fork. | **Documented, no code change — faithful PLC.** `@did-plc/lib`'s `assureValidNextOp` uses the same directory clock, so changing the witness would *fork* the consensus-critical oracle. Bounded: signatures gate every fork, and the anchor's independent **block-time** confirmed head is the cross-check. Detail: `REFERENCE.md` §1 (read-path trust); `directory.ts`. |
| **4c** | MEDIUM | The witness reads anchor state via `starknet_call`, trusting the RPC. | **Documented; real fix deferred.** *(verify-on-read update, 2026-07-02: the Merkle root/proof are gone — the witness now reads the raw op log (`chain`) and re-derives the head; the op *contents* are content-addressed/trustless, but whether it's the DID's true/complete log still comes from the RPC.)* Trustless reads require a **Starknet storage proof against the L1-settled state root** — now over the op-log storage directly (Mode-2 infra; `HISTORY.md` follow-ups). Interim: run your own node, or trust your RPC. Detail: `REFERENCE.md` §1; `starknet.ts`. |

**Deployment consequence of 4a.** The `StoredOp` storage layout changed, so the pre-4a Sepolia
instance (`0x00816c…`) was superseded by a fresh **post-4a redeploy**
(`0x01e3cd42e8481a40b366ef32940e8bc050fd79c924c9b838a6dc0338a08fc5c3`, `deployments/sepolia.json`;
code defaults updated). The roster starts empty — re-import DIDs from genesis before live/mainnet.

## June 2026 internal audit (items 1–6)

| id | sev | finding | resolution |
|---|---|---|---|
| **1** | HIGH | The directory's `nullified` audit-log flag was trusted verbatim; a hostile directory could flip it to force a false `diverged`/`confirmed`. | **Fixed.** The witness discards the flag and re-derives PLC recovery locally from op contents (`deriveLiveChain` / `deriveNullified` + `crypto.ts`/`opverify.ts`), differential-green vs `@did-plc/lib`. |
| **2** | MEDIUM | `auditLog()` cast the HTTP body with no runtime validation or size bound; malformed fields flowed in as `undefined`/`NaN`. | **Fixed.** `parseAuditLog`/`isAuditEntry` (typed validation, hard error on malformed) + `readBoundedText` (streaming cap + `Content-Length` pre-check, 8 MiB). |
| **3** | MEDIUM | The ingest re-encoder (`json_to_ipld`) recursed with no depth limit and read unbounded response bodies. | **Fixed.** `MAX_DEPTH = 64`; `MAX_BODY_BYTES = 32 MiB` on both HTTP reads. |
| **4** | LOW | An unparseable `createdAt` silently defaulted to non-alarming, letting a malformed timestamp suppress `diverged` indefinitely. | **Fixed.** New explicit `error` status (`directory-timestamp-unparseable`), never absorbed into a verdict; CLI exit 1. |
| **5** | INFO | `verify.cairo` duplicated `submit_op`'s fork/authorization logic (silent-drift risk). | **Fixed.** Deleted `verify.cairo`; `state::apply_op` is the single path (`check_prev_link` kept as a tested standalone primitive). |
| **6** | INFO | Stale doc comment in `recovery.cairo` about the clock source. | **Fixed.** Corrected to distinguish `createdAt` (directory time) from `now` (block time in production). |
